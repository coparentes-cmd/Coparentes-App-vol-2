Coparentes — struktura bazy danych i ERD

Źródło: coparentes-backend-main/prisma/schema.prisma · PostgreSQL · 2026-10-07

1. Obiekty (modele Prisma)

  • Workspace — przestrzeń rodziny
  • User — konto (parentA/B, child, observer)
  • UserConsent — audyt zgód RODO
  • Child — profil dziecka
  • Document — sejf dokumentów
  • Session — sesja API
  • PasswordResetToken — reset hasła
  • Thread — wątek czatu
  • ThreadKey — klucz E2E wątku
  • Message — wiadomość
  • MessageUserTag — tag prywatny
  • ExportJob — eksport dowodów
  • LoginOtpChallenge — OTP logowania
  • TrustedDevice — zaufane urządzenie
  • EmailInvite — zaproszenie e-mail
  • CustodySlot / Schedule / Exception — opieka
  • CalendarEvent — kalendarz
  • SwapRequest — zamiana dnia
  • Expense + ExpenseChild — finanse

4. Relacje kluczowe

  • Workspace → wiele User, Child, wątków, wydatków, dokumentów… (często onDelete: Cascade)
  • User ↔ Child opcjonalnie 1:1 (childProfileId / linkedAccount)
  • Thread → Message, ThreadKey (E2E per user)
  • Expense ↔ Child przez ExpenseChild (M:N)
  • Soft-delete konta: User.deletedAt (wiersz zostaje)
